# 🔐 Security Policy — Emerald City Roleplay

Thank you for helping keep **Emerald City Roleplay (ECRP)** secure.

We take security vulnerabilities seriously, especially issues that may affect player accounts, UCP, Discord integration, server data, or the integrity of the roleplay environment.

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability, **please do not publicly disclose it immediately**.

Report the issue privately to the Emerald City Roleplay Development or Management Team through the official Discord:

https://discord.gg/F2DPsUsgRe

When reporting a vulnerability, please provide:

- 📌 A clear description of the vulnerability
- 🔄 Steps to reproduce the issue
- 🎯 The affected command, system, endpoint, or feature
- 📷 Screenshots or video proof when available
- 💥 The potential impact of the vulnerability
- 🛠️ Any suggested mitigation or fix, if available

---

## 🛡️ Security Issues We Accept

Examples include, but are not limited to:

- SQL Injection
- Authentication or authorization bypass
- Permission bypass
- Account or UCP vulnerabilities
- Discord verification vulnerabilities
- Data exposure
- Remote code execution
- Server crashes caused by exploitable input
- Duplication exploits
- Economy exploits
- Buffer overflow
- Format string vulnerabilities
- Game/server exploits
- Privilege escalation

---

## ⚠️ Responsible Disclosure

Please follow responsible disclosure practices.

Do not:

- ❌ Exploit a vulnerability against other players
- ❌ Steal, modify, or delete data
- ❌ Abuse an exploit for personal gain
- ❌ Publish working exploit code before the issue is fixed
- ❌ Share private vulnerability details with unauthorized individuals
- ❌ Attack or intentionally disrupt the server

Security testing should be limited to what is necessary to demonstrate the issue.

---

## 🔎 What Happens After a Report?

After receiving a report, the ECRP Team may:

1. Review and verify the vulnerability.
2. Determine its severity and impact.
3. Apply a temporary mitigation if necessary.
4. Develop and deploy a permanent fix.
5. Document the fix in the project changelog when appropriate.

Not every report will result in a public disclosure.

---

## 🏆 Security Researchers

We appreciate players, developers, and security researchers who responsibly report vulnerabilities.

Valid security reports may receive appropriate recognition from the ECRP Team, depending on the severity and circumstances of the report.

---

## 📋 Security Updates

Security-related fixes are documented in:

`CHANGELOG.md`

Examples of previously addressed issues include SQL Injection, permission bypasses, duplication exploits, format string vulnerabilities, buffer overflow risks, and other security-related bugs.
